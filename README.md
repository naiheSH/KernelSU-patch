# KernelSU 自动更新与使用工具
## 一、项目简介
本项目包含Windows批处理脚本和Linux Shell脚本，旨在便捷地管理KernelSU相关的.ko文件。它能够自动检测KernelSU在GitHub上的最新版本，下载更新，并根据不同的Android系统内核版本对启动镜像进行补丁操作，同时还具备文件管理功能，如重命名和清理镜像文件，帮助用户更高效地使用KernelSU。

## 支持平台
| 平台 | 脚本 | ksud 版本 |
|------|------|-----------|
| Windows | `patch.bat` | `bin/ksud.exe` |
| Linux (x86_64) | `patch.sh` | `bin/ksud` |

## 二、功能特性
1. **自动版本检测与更新**：脚本会查询GitHub上`tiann/KernelSU`仓库的最新版本，与本地记录的版本对比。若有新版本，自动下载指定的.ko文件，确保用户使用的是最新的KernelSU功能。
2. **下载完整性校验**：下载完成后自动检查文件大小，确保.ko文件完整有效，避免因网络问题导致的不完整下载。
3. **版本号安全写入**：仅在所有文件下载成功后才更新本地版本号，防止部分下载失败导致版本号不一致。
4. **多版本.ko文件下载**：支持同时下载适用于不同Android系统内核版本的.ko文件，如`android12-5.10_kernelsu.ko`、`android16-6.12_kernelsu.ko`等，满足多种设备需求。
5. **启动镜像补丁处理**：根据用户选择的GKI版本（对应不同系统内核），使用`ksud boot-patch`命令对启动镜像（`boot.img`或`init_boot.img`）进行补丁操作，使系统支持KernelSU。新版ksud已内置boot image处理能力，无需外部magiskboot工具。
6. **智能等待机制**：补丁操作完成后，采用轮询检测方式等待文件生成，而非固定延时，确保大镜像文件也能正确处理。
7. **文件管理**：下载前自动删除本地已存在的同名.ko文件，避免文件冲突。生成的镜像文件会自动重命名，方便用户识别和管理。还提供清理`img`目录文件的选项，保持工作目录整洁。

## 三、使用方法
1. **环境准备**
    - 确保系统已安装`curl`工具，用于与GitHub进行交互获取文件和版本信息。若未安装，可根据系统类型安装对应版本。
    - 准备好待处理的启动镜像文件，放置在脚本同目录下的`img`文件夹中。
2. **运行脚本**
    - **Windows**：打开命令提示符（CMD），进入脚本所在目录，运行 `patch.bat`。
    - **Linux**：打开终端，进入脚本所在目录，运行 `./patch.sh`。
    - 脚本开始执行：
        - 首先获取GitHub上KernelSU的最新版本号，与本地存储在`ko\version.txt`中的版本号对比。
        - 若版本不同，开始下载最新的.ko文件到`ko`目录，并删除旧文件。
        - 下载完成后检查文件完整性，仅在全部成功后更新版本号。
        - 提示用户选择GKI版本（1-7），根据系统内核版本选择对应选项。
        - 脚本根据选择对启动镜像进行补丁操作，完成后等待文件生成。
        - 查找并将生成的最新镜像文件重命名，方便管理。
        - 最后询问是否删除`img`目录中的所有文件，输入`y`或`n`确认。

## 四、代码结构与原理
1. **版本检测与下载**
    - 使用`curl`命令访问GitHub API（`https://api.github.com/repos/tiann/KernelSU/releases/latest`）获取最新版本信息。
    - 从API响应中提取版本号，对比本地版本号。
    - 利用`curl`的下载功能，结合构建的下载链接下载文件，同时删除本地旧文件。
    - 下载完成后检查文件大小（至少10KB），确保文件完整。
    - 仅在所有文件下载成功后才写入版本号到`version.txt`。
2. **启动镜像补丁处理**：依据用户选择的GKI版本，调用`ksud boot-patch`命令，传入启动镜像路径、对应的.ko文件路径和KMI版本等参数，完成补丁操作。
3. **智能等待**：补丁完成后采用轮询检测（每秒检查一次，最多等待30秒），确保大镜像文件也能正确处理。
4. **文件管理**：查找最新生成的`.img`文件，根据规则重命名。根据用户输入决定是否删除`img`目录下的所有文件。

## 五、问题与解决
1. **下载失败**：可能由于网络问题或GitHub API访问限制导致。检查网络连接，若频繁出现问题，可尝试更换网络环境、等待一段时间后重试，或编辑脚本设置代理。
2. **版本号写入失败**：若`version.txt`文件权限不足或路径错误，会导致写入失败。确保`ko`目录有写入权限，且文件路径正确。
3. **补丁操作失败**：可能是启动镜像文件损坏、.ko文件不兼容或`ksud`版本异常。检查文件完整性，确认工具版本与系统兼容，必要时重新下载相关文件和工具。
4. **文件下载不完整**：脚本会自动检查文件大小，若.ko文件小于10KB则视为下载失败，不会更新版本号，下次运行会自动重新下载。
